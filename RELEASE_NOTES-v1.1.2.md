### Added

- **ESABI v0.3.0 pinned** (`deps/esabi`, git submodule at tag `v0.3.0`) — the
  native accelerator, cli worker/worker bridge, selftest, and smoke harness now
  consume the shared ExternalObject ABI declarations (`esabi_value`,
  `esabi_long`, `esabi_error`, `ESABI_CALL`). ESHTTP keeps ownership of only its
  HTTP API and memory policy; the export surface is unchanged (exactly 8
  exports, no `eshttp_free`).
- **Live gate runner** (`test/live/run-live-gate.mjs` + `test/live/live-estc-gate.jsx`)
  — a deterministic real-Illustrator gate against the project's local mock
  server (no external network), submitted through the bundled Illustrator COM
  tool.

### Changed

- **ESTC-canonical JSX emission** — `dist/eshttp.jsx` (334,142 B) is now
  emitted by the shared toolchain (`extendscript.estc.config.mjs`): esbuild ES5
  IIFE → bundle-local esbuild-helper localization → UglifyJS ExtendScript-safe
  re-emission → parser-output repair → strict ES3 static gate. The side-effect
  entry (`src/jsx-entry.ts`) suppresses descriptor-dependent esbuild export
  helpers entirely; `src/eshttp.jsxinc` is regenerated byte-identical to
  `dist/eshttp.jsx` and is now part of the ESTC static + live-parse gates.
- **No persistent built-in patches** — the artifact no longer prepends the
  `Object.defineProperty` / `Function.prototype.bind` shim. The facade path is
  descriptor-free: guarded instance `__defineGetter__` live getters where the
  engine provides them (plain snapshot fallback otherwise) and a
  plain-assignment session-global publish. Confirmed by the artifact-contract
  suite (no built-in mutation; strict-engine and no-defineProperty sandboxes
  both publish the facade).
- **Build pipeline** — `eshttp-build.mjs` drives the ESTC build, verifies
  embedded-payload byte fidelity after the ESTC pass, composes the merged
  per-bitness accels from pinned sibling artifacts, and runs the ESTC static
  gate on every shipped JSX plus the jsxinc.
- **Live-runner staging precondition** — the gate enforces byte identity
  between the staged `%LOCALAPPDATA%\eshttp\eshttp-cli.exe` worker and the
  canonical built binary (PE-verified) before each run, so repeated runs in one
  Illustrator process are deterministic. Harness precondition only; product
  transport code is untouched.

### Fixed

- **`package-lock.json` repaired** — the v1.1.1 commit globally replaced 28
  dependency `version` fields with the package version (every `@esbuild/*`
  platform package, `esbuild`, and `typescript`; the `resolved` URLs and
  integrity hashes were intact). Restored exactly from the pre-corruption
  parent revision (`24c401a^`) — esbuild/@esbuild 0.28.2, TypeScript 5.9.3 —
  with only the two root package version fields synced to 1.1.2.
  `npm ci --dry-run` succeeds with zero dependency drift.
- **Q12 artifact-contract scans are payload-aware** — the jsxinc checks blank
  the embedded generated ESON/ESB64 bundle literals before scanning for bare
  `require(` / `module.exports`, so generated data strings cannot influence the
  own-code assertion (ESHTTP's own code is unchanged).

### Security

- Unchanged from v1.1.1: host-owned strings on the native boundary, cli
  job-file hardening, pipe lane as local kernel IPC, no firewall rule ever
  modified, native lane returns envelopes only. The shipped artifact now
  patches zero host built-ins.

### Compatibility

- Unchanged: Windows x64/x86 (pipe + native opt-in), macOS socket-only
  cleartext; Illustrator 30.6.0 live-verified (static parse, live parse, and a
  live localhost request). The native binaries are byte-identical to v1.1.1
  (T16 hash check; SHA-256 matches the v1.1.1 release assets), so the
  previously verified native/pipe behavior carries forward unchanged.
